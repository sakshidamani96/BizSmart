# Deploying BizSmart on Render (Blueprint)

`render.yaml` creates two resources in the **Singapore** region, which is closest to India:

| Resource | Type | Plan |
|---|---|---|
| `bizsmart-db` | PostgreSQL | Free |
| `bizsmart` | Web service (Docker): serves the React UI **and** the `/api` backend | Free |

The UI and API share one URL, so there is nothing to configure for CORS or API URLs.

## Steps

1. **Create a GitHub repo you own** and push this project so that `render.yaml` is at the **repository root**:
   ```bash
   git init
   git add .
   git commit -m "BizSmart: Render blueprint"
   git branch -M main
   git remote add origin https://github.com/<you>/bizsmart.git
   git push -u origin main
   ```
2. On <https://dashboard.render.com>: **New → Blueprint**, connect GitHub, and pick the repo.
3. Render shows the resources it will create and asks for **`DEMO_USER_PASSWORD`**. Enter a password for the demo accounts, or leave it blank to use `password123`.
4. Click **Apply**. The first Docker build takes around 5–8 minutes, because it installs npm and Maven dependencies.
5. When the service is **Live**, open `https://bizsmart-xxxx.onrender.com`. The header badge should read **Cloud PostgreSQL Live**.
6. Check health: `https://bizsmart-xxxx.onrender.com/api/health` should return `"status":"UP","database":"CONNECTED"`.

## Environment variables (set by the Blueprint)

| Variable | Purpose |
|---|---|
| `SPRING_PROFILES_ACTIVE=prod` | Uses PostgreSQL and disables the H2 console |
| `DB_HOST/DB_PORT/DB_NAME/DB_USER/DB_PASSWORD` | Injected from `bizsmart-db` (internal network) |
| `JWT_SECRET` | Random signing key generated by Render |
| `SEED_DEMO_DATA` | `true` seeds demo users and 30 products on first boot. It never overwrites existing data. |
| `DEMO_USER_PASSWORD` | Password for the seeded demo accounts |
| `PUBLIC_SIGNUP_ENABLED` | Set `false` after creating your own owner account, to stop strangers registering |
| `CORS_ALLOWED_ORIGINS` | Only needed if another frontend calls this API |

## Going from demo to a real store

1. Register your own owner account, then set `PUBLIC_SIGNUP_ENABLED=false`.
2. For a fresh database without the sample data, set `SEED_DEMO_DATA=false` **before the first deploy**.

## Free-tier limits you should know

- **The free Postgres expires 30 days after creation.** After that, Render gives a 14-day grace period to upgrade before the data is deleted. For anything you want to keep, change the database `plan:` in `render.yaml` to a paid plan such as `basic-256mb`.
- The free web service **sleeps after ~15 minutes idle**. The next visit can take up to a minute while it wakes up; the UI shows "Connecting Cloud API..." meanwhile.
- 512 MB RAM. The JVM flags in the `Dockerfile` are tuned for this.

## Troubleshooting

| Symptom | Fix |
|---|---|
| Blueprint not detected | `render.yaml` must be at the repo root, not in a subfolder |
| Build fails in the Maven stage | Open the deploy log; the error names the Java file and line |
| `/api/health` shows `database: UNAVAILABLE` | Check the DB and service are in the same region and the DB is available |
| Login says "Incorrect email or password" | Use the email (e.g. `owner@bizsmart.in`) and the `DEMO_USER_PASSWORD` you set |
| Browser shows old UI after a deploy | Hard refresh (Ctrl+Shift+R) |
